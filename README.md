# PulsePoint+ — Emerald & Coral

## Update your existing GitHub Pages website
1. Extract this ZIP.
2. In your current GitHub repository, select **Add file → Upload files**.
3. Upload `index.html`, `style.css`, `script.js`, and the complete `assets` folder to the same location as your existing homepage.
4. Commit the changes. Keep your existing GitHub Pages settings.
5. Refresh the deployed website after deployment finishes. If needed, hard-refresh with Ctrl+Shift+R.

## Prefer to paste only one file?
Open `paste-only.html` in a text editor, copy everything, and paste it over your repository's existing `index.html`. This version embeds the CSS, JavaScript, and illustration, so no other project files need updating. It is larger because the image is embedded. Do not paste it into a README or CSS file.

## What changed
- Emerald-and-coral layout based on the chosen mockup.
- Brighter green PulsePoint wordmark with contrasting coral +.
- Colour-coded hotline, navigation and quick-service buttons.
- Press compression, tap ripples, hover lift and keyboard focus rings.
- Reduced-motion support; touch effects do not delay actions or depend on vibration support.
- Compact mobile navigation, scrollable blood table and stacked organ cards.
- Requested display text: NOT TO Organ Transplant Registry.
- Hospital illustration included locally.
- Optional device-only siren, steady screen beacon and copy-location tool.

## Current capabilities
This remains a static frontend prototype. Google Maps embeds/directions, user-permitted browser GPS and telephone links use browser/device services. Internet access is needed for Google Maps and the Font Awesome icon stylesheet. Text labels remain visible if icons cannot load.

Hospital contacts, beds, doctors, distances before GPS, blood stocks and organ listings are unverified sample data. No hospital, transplant registry or dispatch system is connected. Demo login is not authentication; requests are previews and send nothing. Staff updates affect the current tab and reset on reload. The NOT TO label is the requested display wording, not an official integration claim.

No API keys, build step or backend are required for this design. A real service needs verified data, authenticated backend APIs and server-side access controls.
